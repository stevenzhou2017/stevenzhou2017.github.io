### 前三项推荐理由

1. **CRS 把“成功率”拆成沿机构约束的有效进展与偏离约束的浪费**，可直接转化为可诊断、可回放质量指标。
2. **ActiveAlign 把标定从一次性离线步骤变成动作与触觉驱动的闭环对齐**，对 AI+3D、工位漂移和毫米级装配最直接。
3. **汽车软件 Agent 的核心结论是“验证必须是独立、可显式调用的工具”**；这与 AI-in-the-loop Gatekeeper、冷压回路自检及防止 FAE 静默失效高度一致。

## 二、精选条目深度评析

### 1. 约束参考式关节物体操作评测 / *Kinematic Constraint-Referenced Evaluation for Articulated Object Manipulation*

**状态与来源**：首次发表，2026-10-27｜[论文](https://arxiv.org/abs/2610.37550)

**工业问题与机制。** 二元成功率无法说明机器人是否沿铰链、滑轨等真实运动学约束施力。作者提出 Constraint-Referenced Strategy（CRS），把末端 twist 投影到关节轴，分别度量“沿约束进展”和“偏离约束浪费”；它需要关节模型和同轴脚本控制器，但不依赖示教轨迹或学习式裁判。与 VLM judge 相比，CRS 的参照是显式几何约束，可解释且可审计。

**证据质量。** 作者在 74 个仿真关节物体上测试三类迁移失效；门策略迁移到抽屉时，110 次中成功 59 次，但成功轨迹的离轴旋转仍约为抽屉专用策略的 40 倍（1.27 对 0.032 rad/s）。相对脚本参照的判定在关节轴误差至 30° 时不变，绝对阈值约容忍 8°。优点是给出了扰动敏感性；不足是无真实工业铰链/滑轨、磨损、间隙、力矩或安全事件验证。

**工程可落地性。** 计算仅涉及运动学投影，预期适合边缘实时；但关节轴获取、单位/坐标系、阈值标定和代码许可在摘要页未完整报告。失效模式包括错误关节模型、柔性机构、多关节耦合及接触点变化。


### 2. 主动感知对齐 / *ActiveAlign: Aligning Egocentric Manipulation via Active Perception*

**状态与来源**：首次发表，2026-10-27｜[论文](https://arxiv.org/abs/2610.36859)

**工业问题与机制。** 被动观测留下 Real2Sim2Real 对齐误差。ActiveAlign-Waving 通过主动手部运动与可微渲染做手眼标定；ActiveAlign-Touching 再用触觉修正物体对齐。与一次性棋盘格标定不同，它把动作本身当成观测设计，并用接触闭环补足视觉遮挡与尺度误差。

**证据质量。** 作者展示了对未标定开源数据集的仿真环境整理，并在真实 Unitree G1 上完成按钮、滑块等毫米级操作。论文摘要未给出跨相机、跨温度、长期漂移统计，也未报告错误触碰的安全代价；公开结果仍是作者自证。

**工程可落地性。** 需可控探测动作、可微渲染、触觉传感与机器人模型；训练/推理算力、标定时间和代码成熟度未完整报告。触碰过程可能碰撞敏感设备，必须限定速度、力、空间与停机条件。


### 3. 面向安全关键汽车软件的生成与验证 / *Generation and Verification: Human-Agent Collaboration for -Critical Automotive Software Engineering*

**状态与来源**：首次发表，2026-10-26｜[论文](https://arxiv.org/abs/2610.35982)

**工业问题与机制。** 通用 coding agent 强调生成，却难满足需求追踪、MISRA/AUTOSAR 和组织接口约束。系统通过 MCP 暴露 generate、edit、verify 三个独立工具，使用户能对任意代码显式验证；模型再用提示工程或来自 AUMOVIO 量产代码、需求文本和 UML 行为的配对数据定制。

**证据质量。** 两周真实生产项目试点中，verify 是最常用工具，且被用于人工代码而非只检查 AI 输出；75% 开发者偏好更快的提示工程配置。模式检查器显示：提示工程在 C 上违规更少，微调在 C++ 架构模式上更好。局限是样本人数、绝对缺陷率、漏检率和安全缺陷召回未在摘要页报告；开发者偏好不能证明安全性，数据为私有且难独立复现。

**工程可落地性。** MCP 工具边界易与 CI、静态分析和需求系统集成；生产代码/数据许可不公开，推理资源和延迟未报告。最大的已知风险是 agent 跳过 verify、验证器规则覆盖不足，或把“无告警”误解为“安全”。


### 4. 多层物理理解驱动的机器人程序搜索 / *RoboAuto: Autonomous Robot Program Search through Multi-Level Physical Understanding*

**状态与来源**：首次发表，2026-10-27｜[论文与项目](https://arxiv.org/abs/2610.36533)

**工业问题与机制。** Code-as-Policy 常只根据执行成败改程序，不知道对象可供性、场景几何和交互因果。RoboAuto 用三层机制补齐：含技能/可供性/空间关系/动作效果的层次知识库；面向当前场景的 grounding；以及以自设计实验检查阶段效果、区分竞争假设的多阶段规划。

**证据质量。** 作者报告五类基准中，LIBERO-PRO 短任务成功率 89.1%，在 LIBERO-PRO Long/Plus 上平均成功率超过 ASPIRE 两倍，并在三个真实长时精细操作任务上优于 ASPIRE 与 π0.5；还做了跨仿真器/本体迁移和知识库规模实验。局限是完整分母、置信区间、API/模型成本和危险探索次数需从全文/代码核验；自设计实验可能把未知风险转化为真实动作。

**工程可落地性。** 模块化程序比端到端动作更易审计，但知识库维护、场景量测与外部 LLM 延迟可能很高；项目页已公开，代码、权重和许可证可用性需持续核验。


### 5. 人类引导的自适应残差修正 / *When, Where, and What to Correct: Human-Guided Adaptive Residual Correction for Robot Policies*

**状态与来源**：首次发表，2026-10-27｜[论文](https://arxiv.org/abs/2610.37547)

**工业问题与机制。** 模仿策略常只在末端精定位局部失败，全量重训成本高。ARC 冻结原策略，用稀疏人工修正确定“何时启用”和残差探索的低维“方向”，再由 RL 奖励决定最终修正，而不是照抄人工动作。

**证据质量。** 三个真实精密操作任务的平均成功率从 33.3% 提升至 75.0%；人工修正把七关节残差压缩到 2—3 维子空间，并保留 96.0%—97.7% 的修正能量。证据来自真实机器人但任务仅三项；人工干预量、训练样本、最坏失败、跨工位迁移和安全约束未在摘要页完整报告。

**工程可落地性。** 插件式残差层有利于保留已验证基线，但在线 RL 探索、奖励错误和残差叠加可能破坏控制器保证。应限制残差范数、关节/笛卡尔边界及启用区域，并提供一键回退。


### 6. 视频生成与机器人控制共享骨干 / *TAPESTRY: A Single Backbone for Video Generation and Robot Control*

**状态与来源**：首次发表，2026-10-27；CoRL 2026 接收｜[论文与项目](https://arxiv.org/abs/2610.36823)

**工业问题与机制。** 世界模型通常在推理时生成视频，成本高；独立动作头又浪费预训练动力学。TAPESTRY 把动作时间步映射成视频 VAE 潜空间中的单 patch token，在同一 diffusion transformer 内联合训练视频扩散、视频+动作扩散和动作扩散；推理时只用一次 DDIM 生成动作块，不生成完整视频。

**证据质量。** 作者报告消费级硬件上每个动作块 84 ms，并在仿真与真实机器人实验中优于可比 joint video-action 方法。摘要未给出硬件型号、抖动/P99、动作块时长、参数量、故障分布或跨设备数据划分；尚无独立复现。

**工程可落地性。** 84 ms 只说明平均模型延迟，不代表闭环 deadline；需要计入采集、网络、排队和控制周期。共享骨干降低重复计算，但视频预训练数据来源、许可证、显存和部署 SDK 未完整报告。


## 三、结论

本周最值得投入的不是再追求一个更高的端到端成功率，而是把**约束、标定和验证**变成运行时的一等对象。
